Document Ingestion & Docling

What is Document Ingestion?

Converting raw files (PDFs, Word, PowerPoint, etc.) into a format that RAG systems can search and retrieve.

Our Pipeline (6 Steps):

  1. Collection: File upload, batch import, API integration
  2. Parsing: PDF → Text (using Docling), Word/Excel/PPT parsers
  3. Cleaning: Remove headers/footers, preserve structure
  4. Chunking: Split into semantic units (see next section)
  5. Embedding: Convert to vectors (768-1536 dimensions)
  6. Storage: Vector DB, Metadata DB, BM25 Index, Knowledge Graph

Why Docling for Enterprise PDFs?

  • ✅ Preserves structure (tables, lists, headings)
  • ✅ OCR capable for scanned documents
  • ✅ Multi-column layouts parsed correctly
  • ✅ Metadata extraction (author, title, dates)
  • ✅ Open source, no vendor lock-in

Chunking & Agentic Chunking

Why Chunking?

Documents are too large! Enterprise policy doc: 50 pages = 25,000 tokens, but LLM context window is only 4,096 tokens.

Chunking Strategies:

  • Fixed-Size: Split every 500 tokens (❌ splits mid-sentence, loses context)
  • Sentence Boundary: Respect sentences (⚠️ still splits mid-paragraph)
  • Paragraph Boundary: Maintain semantic units (✅ our default)
  • Semantic: Use embeddings to detect topic changes (✅ best quality, slower)
  • Agentic: LLM decides boundaries (✅✅ highest quality, +20% accuracy)

What is Agentic Chunking?

Uses an LLM "agent" to intelligently decide where to split documents, understanding semantic meaning and maintaining logical flow. The LLM analyzes: "Should these segments be combined? Is this a natural topic boundary?"

Agentic Chunking Trade-offs:

Method Quality Speed Cost
Paragraph-based ⭐⭐⭐⭐ Good ⚡⚡ 50ms Free
Agentic ⭐⭐⭐⭐⭐ Excellent ⚡ 2000ms LLM cost (local = $0)

  4. Observe: Complete, coherent answers (not sentence fragments)

Embeddings & Vector Search

What are Embeddings?

Text converted into numbers (vectors) that capture semantic meaning. Similar meanings = close together in vector space.

Example: "neural network" and "deep learning" are close together, but "banana recipe" is far away.

Vector Search Process:

  1. Query → Embedding Model → Query Vector
  2. Compare query vector with all document vectors
  3. Find most similar (using cosine similarity)
  4. Return top-K most similar documents

Our Lab Uses:

  • Model: nomic-embed-text
  • Dimensions: 768 (each chunk becomes a 768-number vector)
  • Vector DB: ChromaDB

Advantages:

  • ✅ Understands meaning, not just keywords
  • ✅ Finds semantically similar content
  • ✅ Handles synonyms and paraphrases

Limitations:

  • ❌ May miss exact keyword matches
  • ❌ Requires embedding model (adds ~10ms latency)

🎯 Exercise:

  1. Go to Settings → ensure Vector Search is ON
  2. Disable all other features (BM25, Hybrid, KG, etc.)
  3. Ask: "machine learning tutorial"
  4. Observe: Finds docs about ML, AI, neural networks (semantic match!)
  5. Note sources and relevance scores
💡 Pro Tip: Vector search alone is good, but combining it with keyword search (BM25) gives even better results!

BM25 Keyword Search

What is BM25?

Best Matching 25 - A probabilistic ranking function for keyword-based search. Traditional search engine technology.

How it works:

  1. Query splits into terms: "neural network training" → ["neural", "network", "training"]
  2. For each document: Count term frequency (TF)
  3. Calculate inverse document frequency (IDF) - rare terms = more important
  4. Score documents, return top-K

BM25 vs Vector Search:

Aspect BM25 Vector Search
Matching Exact keywords Semantic meaning
Speed ⚡⚡⚡ Very fast ⚡⚡ Fast
Synonyms ❌ No ✅ Yes
Exact match ✅ Perfect ⚠️ May miss

🎯 Exercise:

  1. Go to Settings → Turn OFF Vector Search
  2. Turn ON BM25 Search
  3. Ask: "Python programming" (exact keywords)
  4. Note: Fast results, keyword-focused
  5. Try: "coding in Python" → May miss docs without exact "coding" term
💡 Best Practice: Don't choose! Use BM25 + Vector together (Hybrid Search) for best results.

❓ Frequently Asked Questions

About RAG Systems

What is RAG?

RAG (Retrieval Augmented Generation) combines document retrieval with LLM generation. It searches relevant documents, then uses them as context for the LLM to generate accurate, grounded responses.

Why use RAG instead of just an LLM?

RAG provides: 1) Up-to-date information beyond training data, 2) Source attribution for answers, 3) Domain-specific knowledge, 4) Reduced hallucinations, 5) Cost-effective vs fine-tuning.

What's the difference between vector and keyword search?

Vector search finds semantically similar content (meaning-based). Keyword search finds exact term matches. Hybrid search combines both for better results.

Technical Details

What models are being used?

Embeddings: nomic-embed-text. LLM: Llama 3.2 (1B/3B/8B). All run locally via Ollama.

How does knowledge graph help?

Knowledge graphs connect entities, concepts, and documents. They help find related information beyond simple text matching.

What's agentic chunking?

LLM-powered intelligent document splitting that preserves context and semantic meaning, vs simple fixed-size chunks.
